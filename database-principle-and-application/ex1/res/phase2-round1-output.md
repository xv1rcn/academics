# 教务管理系统项目技术方案建议书

## 一、技术架构选型

### 1.1 总体架构模式
本项目推荐采用 **微服务架构 + 前后端分离 B/S 模式** 作为核心架构范式，选型依据如下：

1. **匹配高并发与高可用要求**：针对选课高峰期15000人并发、峰值QPS 5000+的核心压力场景，微服务可实现选课核心服务独立扩容、资源隔离，避免单体架构下单点故障导致整体不可用，支撑系统可用率>=99.95%的目标。
2. **契合模块热插拔与演进需求**：12个业务模块职责边界清晰，微服务架构支持各模块独立部署、独立迭代，满足未来教学业务灵活调整的需求，符合甲方"模块热插拔、标准OpenAPI"的扩展性要求。
3. **前后端分离提升交互体验**：B/S架构无需客户端安装，前后端分离实现前端交互体验优化与后端服务解耦，同时支撑PC门户与移动端统一服务接入。
4. **容灾与运维能力保障**：微服务集群化部署配合主从架构、多可用区部署，可满足RPO<15分钟、RTO<1小时的灾备指标。

### 1.2 前端技术栈选型

| 技术领域 | 选型方案 | 选型理由 |
|---------|---------|---------|
| 核心框架 | Vue 3 + TypeScript + Vite | 国内高校信息化领域主流技术栈，生态成熟 |
| UI组件库 | Element Plus（PC端） | 组件覆盖全面，适配中后台管理系统场景 |
| 移动端框架 | uni-app | 一套代码多端发布 |
| 可视化引擎 | ECharts + DataV | 支撑教学数据驾驶舱、自定义报表 |
| 状态管理 | Pinia | 轻量高效，适配Vue 3生态 |

### 1.3 后端技术栈选型
- **基础框架**：Spring Boot 3.x + Spring Cloud Alibaba 2023.x
- **注册与配置中心**：Nacos
- **API网关**：Spring Cloud Gateway
- **限流熔断**：Sentinel
- **认证授权**：Spring Security + OAuth2.0 + JWT

### 1.4 数据库选型与高并发选课策略

| 数据库类型 | 选型方案 | 适用场景 |
|-----------|---------|---------|
| 关系型主数据库 | MySQL 8.0 主从集群 | 核心业务数据存储 |
| 分布式缓存 | Redis 7.x 集群 | 热点数据缓存、选课库存控制、分布式锁 |
| 分析型数据库 | ClickHouse | 教学数据分析、历史数据聚合查询 |
| 全文检索引擎 | Elasticsearch | 全文检索与复杂条件筛选 |

**高并发选课核心应对策略**：限流削峰+缓存前置+异步落库+乐观锁控量
1. 入口层限流（Sentinel令牌桶）
2. 多级缓存预热（Redis集群）
3. 库存原子控制（DECR原子指令）
4. 消息队列削峰（RocketMQ异步化）
5. 数据库优化（分库分表+读写分离）
6. 资源隔离（选课服务独立集群）

### 1.5 核心中间件选型
- 消息队列：RocketMQ
- 分布式任务调度：XXL-Job
- 链路追踪与监控：SkyWalking + Prometheus + Grafana
- 文件存储：MinIO 对象存储
