# 教务管理系统建设项目需求建议书（详细版）

## 四、核心功能模块详细需求

### 1. 学籍管理中心
- **全生命周期学籍状态管理**：支持从新生入学数据导入、分班编学号、学期注册（含自助注册）、在校状态维护、学籍异动（休/复/退/转专业/转学等）到毕业离校的全流程闭环管理。异动流程可自定义，实现线上申请-审批-执行-归档。
- **电子学籍卡与档案管理**：建立结构化、可配置的电子学籍卡，完整记录学生基本信息、学籍异动历史、奖惩记录、毕业结论等。支持附件上传与档案电子化。
- **大类分流与专业确认**：支持按成绩绩点、志愿、综合测评等多规则模型进行专业分流，支持学生端填报志愿、院系审核、结果公示与学籍自动变更。
- **证明材料自助服务**：与电子签章系统集成，学生可在线申请并自助下载带防伪验证码/电子签章的在读证明、学籍证明、毕业证明（英文版需支持模板自定义）等。
- **学信网数据同步**：提供与教育部学信网的数据自动同步接口，支持新生学籍电子注册、在校生学年电子注册、学历学位证书电子注册的批量上报与状态跟踪。

### 2. 培养方案管理系统
- **版本化方案编制**：支持培养方案按年级、专业进行版本化管理，提供在线编辑器，支持结构化录入培养目标、毕业学分要求、课程体系（通识、学科基础、专业、实践等模块）。
- **柔性修读规则引擎**：可图形化配置各模块的必修/选修学分、课程分组、先修后续关系、互斥规则、跨模块替代关系等，作为选课与毕业审核的底层规则。
- **方案变更与审批流**：支持培养方案的调整申请、对比高亮显示变更内容、多级审批（院系/教务处）流程，审批通过后自动同步至当前适用版本。
- **辅修/微专业方案管理**：独立管理辅修专业、微专业、双学位等培养方案，支持与主修方案学分互认规则的配置。
- **方案执行对照视图**：以雷达图、进度条等形式，直观展示每位学生个人已修课程与培养方案的匹配度，辅助学生和导师进行学业规划。

### 3. 开课与排课管理系统
- **教学任务落实**：依据培养方案自动生成学期开课任务，支持多人多部门协同落实任课教师、合班策略、排课特殊需求（如周次、节次、教室类型偏好等），并支持教学任务的增删改和审核。
- **智能排课引擎**：基于约束满足优化算法，支持设置教室容量、多媒体类型、校区、教师时间回避、班级课表均衡度等多维约束，一键自动排课，并提供多套方案供选择。
- **可视化调课与冲突检测**：提供图形化课表界面，支持拖拽式调课。任何排课变动均实时检测并醒目提示教师、班级、教室三者间的时间/地点冲突。
- **教室资源池化管理**：建立全校教室（含实验室、机房）的基础信息库，支持分校区、楼宇、类型进行管理。系统自动调度教室资源，并与调停课联动，实现教室借用、归还与排课的实时同步，杜绝黑用。
- **学期课表多终端发布**：自动生成并发布行政班课表、教师个人课表、教室课表、学生个人（选课后）课表，支持iCal日历格式订阅。

### 4. 选课管理系统
- **多轮次多策略选课**：支持预选（意愿值/积分制）、正选（即选即得/抽签）、补退选、跨专业/跨年级选课等多轮次设置。可针对不同学生群体（如不同年级、专业）配置不同的选课时间窗口和可选课程范围。
- **高并发弹性选课**：基于微服务架构，选课核心模块支持独立弹性伸缩。系统须能承载全校规模的集中选课并发压力，提供排队、限流机制，并给予学生友好的实时反馈。
- **智能选课推荐**：根据学生培养方案完成度、历史选课记录和学业进度，为学生主动推荐应修课程，并标记推荐优先级，降低学生选课盲目性。
- **多维冲突检测**：在选课过程中，实时检测时间冲突、考试安排冲突、先修课程未完成、性别限制、年级限制、已选课程互斥等规则，并即时阻断或给出明确提示。
- **选课数据实时分析**：向管理者提供选课期间的实时看板，展示各课程实时选课人数、课容量、中签率、选课学生分布等，辅助动态调整课堂容量或增开教学班。

### 5. 考务管理系统
- **智能排考**：根据课程考核方式（考试/考查）、教学班人数、学生个人选课结果，综合考虑考场容量、座次间隔、同一学生考试时间不冲突、监考教师工作量均衡等约束，自动编排考试时间、地点和监考人员。
- **多维考试日程发布与查询**：自动生成并发布学生个人考试日历、教师监考日历、班级考试日程、考场占用日程等视图。
- **监考全流程管理**：支持线上监考任务指派、推送、确认、替换申请流程，记录监考到位情况，可灵活设置监考费核算规则。
- **缓考与补考管理**：支持学生在线申请缓考（附证明材料），审批通过后自动进入补考名单库。补考安排可独立或与下一学期考试合并编排。
- **考试过程材料电子化**：集成考场签到（支持扫码/人脸识别）、违纪作弊记录录入、考场情况报告表在线提交等功能，实现考试过程无纸化。

### 6. 成绩管理系统
- **多元化成绩录入**：支持百分制、五级制、两级制、自定义等级制等多种方式。教师可在线或通过移动端分阶段录入平时、期中、期末及实验成绩，系统按自定义公式自动计算总评成绩。
- **成绩提交与审核**：实行"教师录入-教研室/院系审核-教务处分级发布"的管控流程。成绩提交后即锁定，修改须发起"成绩变更申请"，经审批后留痕修改，全程可追溯。
- **绩点与排名计算**：支持多种GPA计算标准（如标准4.0、北大4.0、加权平均分等）的灵活配置，可出具专业排名、班级排名报告。
- **成绩单服务**：支持在校生和校友通过自助服务终端或线上渠道，申请带防伪电子签章的官方成绩单（中英文），支持纸质成绩单的批量套打。
- **学业预警引擎**：基于自定义规则（如不及格学分累计、核心课程未通过等），自动触发学业预警，生成预警学生清单并通过消息中心推送至学生本人、辅导员和导师。

### 7. 毕业与学位审核管理系统
- **审核规则模型化**：将培养方案中的毕业与学位授予要求，转化为计算机可执行的审核模型，包括总学分、分类学分、必修课通过、绩点/外语/计算机等特殊要求。
- **多批次批量自动化审核**：支持秋季、春季、夏季等多批次预审与终审。可一键对全体预计毕业生进行批量自动审核，瞬间输出"通过"、"待定"、"不通过"名单及详细原因。
- **审核结果溯源与反馈**：学生对审核结果有疑义时，可点击查看具体未达标的原因（如"缺1学分公共选修课"），并可在线申诉。教务人员可查看每位学生的审核判定过程全记录。
- **证书管理**：管理毕业证书、学位证书编号，支持批量生成、导出印制数据，确保证书编号的唯一性与连续性，并与学信网学位报送系统对接。
- **校友服务**：支持毕业生学历学位网上验证、证书电子版查询等服务。

### 8. 实践教学管理模块
- **毕业论文（设计）全流程管理**：覆盖选题、开题报告、中期检查、论文查重（需对接主流查重服务接口）、指导教师评阅、盲审安排、答辩分组、成绩评定等全流程线上管理。
- **实习实训管理**：支持实习基地信息库维护、实习计划申报、学生实习岗位匹配、过程日志填报、实习单位评价、保险购买登记等功能，实现实习过程可监控。
- **创新创业学分认定**：提供学生竞赛获奖、发表论文、获得专利、技能证书、创业实践等成果的线上申报、审核与学分认定功能，可自动冲抵相关选修课学分。
- **实验教学管理**：支持实验室排课、开放预约、实验项目管理、实验报告在线提交与批改，与排课系统、成绩系统联动。

### 9. 教学质量评价系统
- **多维度评价体系配置**：支持学生评教、督导评价、同行评价、教师自评、领导评价等。可灵活配置各类评价问卷的指标、权重、适用范围和有效时间。
- **评价过程监控与催办**：实时监控各学院、各班级的评价完成率，支持系统自动催办消息推送，确保评价数据样本量。
- **评价结果统计与反馈**：自动生成教师个人、课程、学院的教学质量分析报告，支持评教得分趋势分析、评语关键词云分析。评价结果可在授权后向教师本人匿名反馈。
- **数据关联应用**：评价结果可与教师绩效考核、职称评定系统数据共享，可关联课程改进、教师教学发展档案。

### 10. 师生服务门户与移动端
- **统一服务门户**：为师生提供风格统一、操作一致的PC Web端和移动端（支持微信企业号/服务号、原生APP、HTML5自适应）入口，功能无差别覆盖。
- **任务驱动的个人工作台**：为不同角色（学生、教师、教务员、管理者）量身定制工作桌面，集中展示待办事项（如待审批申请、待录入成绩）、日程安排、关键通知和个人数据概览。
- **精准消息推送中心**：建立多通道消息中心，支持向特定范围用户推送系统通知、业务提醒（如选课、缴费、考试、成绩发布）、教学预警等，支持微信模板消息、短信、邮件等渠道。
- **7×24小时智能问答**：集成智能客服机器人，加载教务业务知识库，解答常见问题，对复杂问题可自动转接人工留言或工单。

### 11. 教学数据管理与分析决策平台
- **校领导驾驶舱**：面向校领导的一屏总览界面，实时展示在校生总数、开课门次、教室利用率、评教优良率、学业预警总人数等核心KPI，支持下钻至学生个体详情。
- **院系教学运行看板**：为各院系管理者提供本院教学运行监控视图，包括本院学生学籍异动、课程开出率、学生成绩分布、教授为本科生上课率等。
- **专业与课程分析**：对专业建设质量进行画像，分析课程目标达成度、课程对毕业要求支撑矩阵。支持课程数据横向对比与历史趋势分析。
- **自定义报表工具**：提供拖拽式报表设计器，授权用户可从数据仓库中自选字段，灵活创建、保存和订阅个性化数据报表，支持定时生成与邮件分发。

### 12. 系统管理与安全保障模块
- **精细化权限管理**：采用基于角色的访问控制（RBAC），角色、权限粒度可细化至菜单、按钮、数据行（如院领导只能看到本院数据）。支持岗位分离，如系统管理员、安全审计员、业务操作员三权分立。
- **全流程日志审计**：记录所有用户的关键操作日志（增、删、改、查、导出、登录），包括操作时间、IP、内容快照，日志不可篡改、删除，并提供在线查询与分析工具。
- **数据安全与隐私保护**：支持静态数据加密存储，关键业务字段（如身份证号、手机号）在前端展示和接口传输时进行脱敏处理。所有API接口传输均须采用HTTPS加密。
- **信创环境适配**：系统须支持在主流国产服务器、操作系统、数据库及中间件上部署和稳定运行，并提供适配清单和性能测试报告。

## 五、非功能性需求

### 1. 性能要求

| 指标项 | 具体要求 |
| :--- | :--- |
| **并发用户数** | 支持不少于 **30,000** 名在校生、 **3,000** 名教师的同时在线。 |
| **关键业务并发** | 选课高峰期，核心选课模块应能承载不低于 **15,000** 的并发用户数。 |
| **响应时间** | 一般查询类操作平均响应时间 < **1秒**；复杂统计分析类操作 < **3秒**。选课、成绩提交等关键事务类操作，在最大并发下，95%的请求响应时间 < **5秒**。 |
| **数据吞吐量** | 系统应能处理百万级数据量的成绩计算、毕业审核等批量任务，关键任务要求在 **2小时内** 完成。 |

### 2. 安全性要求

- **身份认证**：必须无缝对接学校统一身份认证平台（CAS/Shibboleth/OAuth2），支持单点登录(SSO)和双因素认证。杜绝系统自身建立独立的用户密码体系。
- **权限控制**：必须实现基于角色的访问控制（RBAC），并支持数据权限（仅能查看管理授权范围内的数据，如本院系、本班级）。
- **数据加密**：所有Web请求必须采用HTTPS。关键个人信息（身份证号、手机号、家庭住址）和数据文件须加密存储。数据库备份文件须加密。
- **安全审计**：提供不可抵赖、不可篡改的全量操作日志记录。必须符合GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》中不低于**二级等保**的要求。
- **应用安全**：必须能抵御常见的Web攻击（如SQL注入、跨站脚本XSS、跨站请求伪造CSRF等），须在交付前提供第三方安全渗透测试报告。

### 3. 可用性要求

- **系统可用率**：核心业务系统需保证 **7×24小时** 不间断运行，年度非计划停机时间累计不超过 **4.38小时**，系统可用率不低于 **99.95%**。
- **容灾备份**：须提供两地三中心或同等保护级别的应用级容灾方案。数据库支持实时同步，实现RPO(Recovery Point Objective，恢复点目标) < **15分钟**，RTO(Recovery Time Objective，恢复时间目标) < **1小时**。
- **故障恢复**：关键服务应采用集群化部署，单节点故障时服务不中断。系统应具备自动健康检查和故障报警机制。

### 4. 可扩展性要求

- **业务扩展**：系统架构应支持未来新增功能模块的热插拔部署，新增或修改业务模块不影响核心业务运行。
- **接口开放**：须提供丰富的标准化OpenAPI接口，支持第三方应用的安全集成和数据交互，接口文档需详尽、规范。
- **技术扩展**：支持水平扩展，通过增加服务器节点即可线性提升系统处理能力，无需修改应用代码架构。

## 六、对乙方的投标要求

### 1. 投标方资质要求

- 投标方必须是中华人民共和国境内注册，具有独立法人资格的企业，持有有效的营业执照。
- 须具备软件能力成熟度模型集成CMMI3级及以上认证，或同等水平的资质证明。
- 须具有不少于 **3个** 近五年内（以合同签订日期为准）在"双一流"建设高校或同层次高校成功实施的教务系统项目案例，且单个合同金额不低于 **人民币200万元**。需提供合同及验收报告证明。
- 拟派项目经理须具有PMP或信息系统项目管理师（高级）证书，且有至少1个同类项目的全过程管理经验。项目实施核心骨干成员需在本公司有连续一年以上社保记录。
- 本项目不接受联合体投标，严禁转包，关键模块（如排课、选课、成绩、毕业审核）严禁分包。

### 2. 交付物清单

- **软件产品**：包括系统安装程序、所有功能模块源代码（需开放，便于学校二次开发）、数据库全量脚本。
- **技术文档**：系统需求规格说明书、系统设计说明书（概要及详细设计）、数据库设计说明书（含ER图及数据字典）、API接口文档。
- **用户与部署文档**：系统管理员手册、用户操作手册（分角色）、系统部署与运维手册、系统测试报告（含功能、性能及安全测试）。
- **培训资料**：为不同岗位角色录制的培训视频、场景化操作指南PPT。
- **项目过程文档**：项目总体计划、周报、里程碑评审报告、需求变更确认单。

### 3. 工期与里程碑要求

| 阶段 | 任务 | 要求 |
| :--- | :--- | :--- |
| **第一阶段** | 项目启动、需求详设 | 合同签订后 **1个月内** 完成，输出经双方确认的《需求规格说明书》和《系统设计说明书》。 |
| **第二阶段** | 基础平台与核心业务研发部署 | 合同签订后 **6个月内** 完成，核心模块（学籍、培养方案、排课、选课、成绩）须完成开发、测试并上线试运行。 |
| **第三阶段** | 全部业务模块上线与数据迁移 | 合同签订后 **10个月内** 完成所有系统模块的部署、联调与历史数据清洗迁移，系统整体切换上线。 |
| **第四阶段** | 初验 | 系统全面上线稳定运行 **1个完整学期** 后，进行初步验收。 |
| **第五阶段** | 终验 | 初验通过后，再稳定运行 **1个完整学年**，期间无重大遗留问题，进行最终验收。 |

### 4. 售后服务与技术支持要求

- **质保期**：自项目终验合格之日起，提供不少于 **3年** 的免费原厂质保和驻场服务。质保期内，若因系统自身缺陷导致的故障，一切维护费用由投标方承担。
- **驻场服务**：质保期内，须提供至少 **1名** 有经验的技术工程师在项目现场进行驻场，负责系统巡检、故障排查、即时响应和日常咨询。
- **响应时间**：接到故障报修后，须 **10分钟内** 响应。一般性故障 **1小时内** 解决；严重故障（系统核心功能无法使用）须在 **30分钟内** 到达现场处理， **4小时内** 恢复业务。
- **系统升级**：质保期内，免费提供系统补丁和同软件版本的功能升级。投标方须承诺，在系统架构发生重大升级时，学校有权以优惠价格获得升级服务。
- **知识转移**：投标方须制定详细的知识转移计划，通过现场培训、结对工作等方式，保证学校技术团队能独立完成系统的日常运维、配置管理和简单二次开发。
