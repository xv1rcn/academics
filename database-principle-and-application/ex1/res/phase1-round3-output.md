## 一、用户角色定义

本系统覆盖全校教务管理相关干系人，根据职责和使用场景，定义以下八类核心用户角色。系统须支持为同一物理人分配多个角色，不同角色在登录后呈现差异化的工作台。

| 序号 | 角色名称 | 职责描述 | 典型使用场景 |
| :--- | :--- | :--- | :--- |
| **1** | **学生** | 系统的核心服务对象。完成培养方案指引下的选课、课表查看、成绩查询、学籍异动申请、评教、证明材料办理等个人学业事务。 | • 选课期登录系统进行选课、退课<br>• 查看个人课表与考试安排<br>• 查询学期成绩与绩点排名<br>• 线上申请在读证明并下载<br>• 期末对授课教师进行教学评价 |
| **2** | **任课教师** | 课程教学的执行者。负责课程成绩录入、提交、变更申请，查看个人课表与选课名单，进行调停课申请，教室借用等。 | • 学期末登录系统录入并提交学生成绩<br>• 查看教学班学生名单与课表<br>• 因病因事在线申请调停课<br>• 自助打印成绩登记表 |
| **3** | **教务管理员** | 学校及学院两级教务办公室的工作人员。负责培养方案维护、开排课、选课策略配置、考务安排、学籍状态管理、毕业审核执行等核心业务操作。 | • 配置选轮次、抽签规则与可选课范围<br>• 执行智能排课并手工微调<br>• 编排期末考试并发布监考任务<br>• 处理学籍异动审批<br>• 执行毕业生批量审核 |
| **4** | **教学秘书/辅导员** | 院系层面的学生事务与教务协调者。主要承担本院学生成绩单打印、学业预警名单分发、评教催办、毕业论文流程推动等辅助管理职能。 | • 查看本院学生的学业预警名单并定向沟通<br>• 监控本院学生评教完成率并催办<br>• 辅助本院教师完成成绩提交<br>• 线下处理选课特殊申请 |
| **5** | **教学院长/系主任** | 院系教学工作的管理决策者。负责本院培养方案修订审核、开课任务审批、教学运行状态监控、教师工作量查看等。 | • 审核本院各专业新版培养方案<br>• 查看本院本学期开课率与教授授课率<br>• 分析本院学生成绩分布与课程不及格率 |
| **6** | **校领导** | 学校层面的宏观决策者。通过驾驶舱查看全校教学运行核心指标，为资源配置和政策制定提供依据。 | • 登录领导驾驶舱，查看全校教室使用率、学业预警总览<br>• 下钻查看具体专业建设评估报告 |
| **7** | **系统管理员** | 信息中心的技术运维人员。负责用户与权限管理、系统参数配置、日志审计、数据备份恢复、系统性能监控等。 | • 为新入职教师批量创建账号并授权<br>• 查看系统操作日志，排查异常行为<br>• 执行学期末数据封存与备份 |
| **8** | **外部系统/接口用户** | 需要与教务系统进行数据交换的其他业务系统，如人事、学工、财务、研究生系统等，通过API接口进行自动化数据互访。 | • 人事系统向教务系统同步新进教师基本信息<br>• 财务系统获取学生学籍注册状态以控制缴费<br>• 学工系统获取学生违纪信息以辅助评优 |

## 三、核心业务规则

1. **培养方案必须刚性约束选课与毕业**
2. **学生选课须通过多维度实时冲突检测**
3. **排课与排考须严格遵循"人、时、空"三不冲突原则**
4. **成绩数据遵循"提交即锁定、修改必留痕"原则**
5. **毕业资格与学位授予必须通过系统自动批量审核，而非人工判定**
6. **关键操作必须遵循"三权分立"的权限管控原则**

## 四、期望的系统价值

1. 教务管理效能实现跨越式提升（核心流程耗时减少 60%-80%）
2. 显著降低管理成本与物料消耗（年减少纸质文件 10万份以上）
3. 彻底杜绝因数据不一致导致的业务差错
4. 推动"以学生为中心"的教学服务体验革命
5. 为科学决策提供实时、精准的数据支撑
