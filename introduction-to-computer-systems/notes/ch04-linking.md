# 第4章 程序的链接

> 本章在考试中**独立但必考**——符号解析规则与重定位计算几乎每年出现。学完本章，你将理解 `.o` 文件如何"拼合"成一个可运行程序。

---

## 4.1 编译、汇编和静态链接

<a id="sec4-1-1"></a>
### 4.1.1 编译和汇编  ★★

#### 📌 考点概括
理解编译器和汇编器的职责分工，掌握各阶段输入/输出文件的扩展名与内容。

#### 📖 详细讲解

C 源程序变为可执行文件经历四个阶段（参见 [编译四阶段](./ch01-overview.md#sec1-2-2)）：

```
main.c ──cpp──► main.i ──cc1──► main.s ──as──► main.o ──ld──► prog
 预处理(.c→.i)   编译(.i→.s)   汇编(.s→.o)   链接(.o+.a→a.out)
```

**编译器 (cc1)** 与 **汇编器 (as)** 的职责分工：

| 职责 | 编译器 (cc1) | 汇编器 (as) |
|------|-------------|------------|
| 输入 | `.i` (预处理后 C 源码) | `.s` (汇编文本) |
| 输出 | `.s` (汇编) | `.o` (可重定位目标文件) |
| 理解 | C 语义、类型系统 | 指令编码、ELF 格式 |

> **关键差异**：编译器理解"变量"和"类型"，汇编器只理解指令助记符→机器码的映射。汇编器不关心 `int x = 5` 的语义，它只看到 `.data` 中的一个 `.long 5`。

---

<a id="sec4-1-2"></a>
### 4.1.2 可执行目标文件的生成  ★★

#### 📌 考点概括
链接器的两大核心任务——**符号解析**与**重定位**，是本章全部内容的主线。

#### 📖 详细讲解

链接器（`ld`）将多个 `.o` 和静态库 `.a` 合并为可执行文件：

1. **符号解析**：将每个符号引用与其唯一定义关联，找不到或强符号多重定义则报错。
2. **重定位**：编译/汇编时未知最终地址（用 0 占位），链接器合并同类节后确定每条指令/变量的最终地址并修正所有引用。

```
main.o ──┐                       符号解析: main→call foo → 找到 foo.o 中定义
foo.o  ──┼──► ld ──► prog        重定位: foo.o 中占位地址 → 替换为最终绝对地址
libc.a ──┘
```

## 4.2 目标文件格式

<a id="sec4-2-1"></a>
### 4.2.1 ELF 目标文件格式  ★★★

#### 📌 考点概括
ELF 文件由 **ELF 头 + 节头表 + 程序头表** 构成，**链接视图看节头表、执行视图看程序头表**。

#### 📖 详细讲解

```
       链接视图 (静态)                   执行视图 (动态)
      ┌──────────┐                     ┌──────────┐
      │  ELF 头   │                     │  ELF 头   │
      ├──────────┤                     ├──────────┤
      │ 程序头表  │(可选)               │ 程序头表  │← 加载器需要
      ├──────────┤                     ├──────────┤
      │   节 1    │                     │   段 1    │ (.text+.rodata → R+E)
      │   节 2    │                     ├──────────┤
      │   ...    │                     │   段 2    │ (.data+.bss → R+W)
      │   节 n    │                     ├──────────┤
      ├──────────┤                     │    ...    │
      │  节头表   │← 链接器需要          └──────────┘
      └──────────┘
```

- **ELF 头**：魔数 `0x7fELF`、文件类型(REL/EXEC/DYN)、入口地址、表偏移。
- **节头表**：描述每节名称/类型/地址/偏移/大小，链接器据此合并同类节。
- **程序头表**：仅可执行文件/共享库有，将同权限节打包为"段"供加载器映射。

> 记忆：**可重定位文件用节头表，可执行文件用程序头表**。

---

<a id="sec4-2-2"></a>
### 4.2.2 可重定位目标文件格式  ★★★

#### 📌 考点概括
熟记 **.text / .rodata / .data / .bss / .symtab / .rel.text / .rel.data** 七个核心节的作用。

#### 📖 详细讲解

典型 `main.o` 的节布局：

```
┌──────────┬───────────────────────────────────────┬────────┐
│  ELF 头   │                                       │        │
├──────────┼───────────────────────────────────────┼────────┤
│ .text    │ 编译后的机器代码                        │ 可执行  │
│ .rodata  │ 只读数据: 格式串、switch跳转表（参见[第3章跳转表编译](./ch03-machine-level.md#sec3-4-2)）       │ 只读    │
│ .data    │ 已初始化的全局/静态变量                  │ 可读写  │
│ .bss     │ 未初始化全局/静态变量 (不占磁盘!)         │ 可读写  │
│ .symtab  │ 符号表: 本模块定义和引用的符号            │ 元信息  │
│ .rel.text│ .text 节的重定位信息                    │ 元信息  │
│ .rel.data│ .data 节的重定位信息                    │ 元信息  │
│ .strtab  │ 字符串表                               │ 元信息  │
├──────────┼───────────────────────────────────────┼────────┤
│          │ 节头表                                 │        │
└──────────┴───────────────────────────────────────┴────────┘
```

**速记**："代码去 text，只读去 rodata，初始去 data，未初去 bss，符号找 symtab，重定位在 rel。"

> **常考点：`.bss` 节不占磁盘空间**，仅节头表记录加载后需分配多少字节全零内存。未初始化变量按 C 标准默认为 0。

关于 `.rodata` 更多细节参阅 [第3章 数据的对齐与分配](./ch03-machine-level.md#sec3-5-4)。

---

<a id="sec4-2-3"></a>
### 4.2.3 可执行目标文件格式  ★★★

#### 📌 考点概括
与 `.o` 的本质区别：地址已确定、程序头表引导加载、节合并为段。

#### 📖 详细讲解

| 属性 | 可重定位文件 (.o) | 可执行文件 (a.out) |
|------|-------------------|-------------------|
| ELF 类型 | ET_REL | ET_EXEC |
| 虚拟地址 | 尚未分配 | 已确定最终地址 |
| 入口点 | 无 | 有 (`_start`) |
| 程序头表 | 无 | 有（必要） |
| 外部引用 | 未解析 | 已全部解析 |

加载器按程序头表将段映射到虚拟地址空间：

```
程序头表示例:
┌─────────────┬──────────┬────────┬──────┬──────┐
│  段类型      │ 虚拟地址  │  大小   │ 标志   │ 对齐  │
├─────────────┼──────────┼────────┼──────┼──────┤
│ PT_LOAD(代码)│ 0x400000 │ 0x85c  │ R+E  │ 4KB  │
│ PT_LOAD(数据)│ 0x600000 │ 0x230  │ R+W  │ 4KB  │
└─────────────┴──────────┴────────┴──────┴──────┘
```

`.text` + `.rodata` → 代码段（R+E）；`.data` + `.bss` → 数据段（R+W）。同一段内所有节共享相同权限。

---

<a id="sec4-2-4"></a>
### 4.2.4 可执行文件的存储器映像  ★★

#### 📌 考点概括
加载后虚拟地址空间布局：只读段与可读写段分离，`.bss` 由加载器清零分配。

#### 📖 详细讲解

Linux x86-64 进程经典虚拟地址布局：

```
0x00000000 ┌──────────────┐
           │  NULL 未映射   │ ← 捕获空指针解引用
0x00400000 ├──────────────┤
           │  代码段(R+E)  │ .text + .rodata
           ├──────────────┤
           │  数据段(R+W)  │ .data + .bss
           ├──────────────┤
           │  堆 (Heap)    │ ← malloc, brk 向上增长
           │      ↓       │
           │              │
           │      ↑       │
           │  栈 (Stack)   │ ← 局部变量, 向下增长
           ├──────────────┤
           │  内核空间     │ 用户态不可访问
0xFFFFFFFF └──────────────┘
```

#### 🔍 举例推演

程序头表：代码段 `vaddr=0x400000, filesz=0x85c, memsz=0x85c`；数据段 `vaddr=0x600000, filesz=0x200, memsz=0x230`。`.bss` 大小 = `0x230−0x200=0x30` (48字节)，起始于 `0x600200`，由加载器清零。

## 4.3 符号表和符号解析

<a id="sec4-3-1"></a>
### 4.3.1 符号和符号表  ★★★

#### 📌 考点概括
三类符号（全局/外部/局部）与 COMMON 伪节的区分；.symtab 条目的字段含义。

#### 📖 详细讲解

**符号分类**：

| 符号类别 | 定义方式 | 可见范围 | .symtab 绑定 |
|---------|---------|---------|-------------|
| 全局符号 | 非 static 函数/已初始化全局变量 | 可被其他模块引用 | STB_GLOBAL |
| 外部符号 | `extern` 声明，未在本模块定义 | 仅引用 | STB_GLOBAL, UND |
| 局部符号 | `static` 修饰的函数/变量 | 仅本模块 | STB_LOCAL |

关于 `static` 局部符号的作用域，参阅 [第3章 结构体与局部变量](./ch03-machine-level.md#sec3-5-2)。

**COMMON 伪节**：未初始化全局变量（`int x;`，**不是** `int x = 0;`）编译时置入 COMMON 而非 `.bss`。当多个 `.o` 定义同名未初始化变量时，COMMON 允许多重——链接器选 size 最大者合并。

> **为什么不是 .bss？** 编译器无法预判其他 `.o` 是否有强符号定义（如 `int x = 5;`），COMMON 将最终裁决推迟到链接时。

**符号表条目** (`Elf64_Sym`)：

```
┌────st_name───┬──st_info──┬─st_other─┬──st_shndx─┬───st_value──┬──st_size──┐
│   4 bytes    │  1 byte   │  1 byte  │  2 bytes  │   8 bytes   │  8 bytes  │
├──────────────┼───────────┼──────────┼───────────┼─────────────┼───────────┤
│   名字索引    │ 类型+绑定  │   保留    │ 所在节索引  │   符号地址   │  符号大小  │
└──────────────┴───────────┴──────────┴───────────┴─────────────┴───────────┘
```

`st_shndx = SHN_UNDEF` (0) → 外部未定义引用；`SHN_COMMON` (0xFFF2) → COMMON 伪节。

---

<a id="sec4-3-2"></a>
### 4.3.2 符号解析  ★★★

#### 📌 考点概括
**强符号 / 弱符号**定义与解析决策树——本章最高频的选择/判断题考点。

#### 📖 详细讲解

| 符号类型 | 定义 | 示例 |
|---------|------|------|
| **强符号** | 函数定义、已初始化全局变量 | `int x = 1;` `void foo(){}` |
| **弱符号** | 未初始化全局变量（COMMON中） | `int x;` |

**多符号解析决策树**：

```
    同名符号集合
         │
         ▼
    ≥2 个强符号? ──Yes──► 链接错误: multiple definition
         │
        No
         ▼
    有 1 个强符号? ──Yes──► 选该强符号，忽略所有弱符号
         │
        No (全部弱)
         ▼
    有弱符号? ──Yes──► 任选其一（通常选 size 最大者）
         │
        No
         ▼
    报错: undefined reference
```

**三句话规则**：(1) 不允许多个强符号同名 (2) 一强覆盖多弱 (3) 全弱时任选其一。

#### 🔍 举例推演

链接 `a.o`(`int x;` 弱/4B)、`b.o`(`double x;` 弱/8B)、`c.o`(`int x=5;` 强/4B)：1强+2弱 → 选 `c.o` 的 `x=5`。**陷阱**：若 `a.o` 和 `b.o` 均为强符号 → `multiple definition of x`，链接失败。

#### ✏️ 真题训练

> **题1 (判断)** 链接器把所有未初始化全局变量视为弱符号，所有函数定义视为强符号。

**答案**：正确。未初始化全局变量入 COMMON 为弱符号；函数定义总是强符号。`static` 局部符号不参与跨模块解析。

> **题2 (选择)** 链接 `a.o`(`int x;`) 和 `b.o`(`double x;`)，均无初始化，无其他模块定义 x，则：
> A. 报错 multiple definition  B. 选 `a.o` 的 x  C. 选 `b.o` 的 x  D. 选 size 较小者

**答案**：C。两个弱符号→选 size 最大（`double` 占 8 字节）。链接成功但若 `a.o` 以 4 字节访问而实际分配 8 字节，可能数据错乱。

<a id="sec4-3-3"></a>
### 4.3.3 与静态库的链接  ★★★

#### 📌 考点概括
**单遍扫描算法 + 库顺序依赖**——"被依赖者放后面"是核心铁律。

#### 📖 详细讲解

静态库 (.a) 是 `.o` 的归档包。链接器**仅拉入能解析当前未定义符号的 .o 成员**。单遍扫描算法（维护 E=已合并, U=未解析, D=已定义）：

```
按命令行顺序从左到右扫描 f:
  if .o: E∪={f}; D∪=f定义的符号; U=(U∪f引用的符号)−D
  if .a: 遍历成员 m, 若 m 定义了 U 中某符号:
        E∪={m}; D∪=m符号; U=(U∪m引用)−D
扫描结束: if U≠∅ → undefined reference
```

> **核心规则**：`.a` 必须放在引用它的 `.o` 之后，链接器不回头。

```
# 错误: -lm 在前 → U 空，无.o被拉入 → sin 未解析
$ gcc -lm main.o              → undefined reference to sin

# 正确: main.o 先处理 → U={sin} → -lm 拉入 sin.o
$ gcc main.o -lm
```

#### 🔍 举例推演

> **场景**：`main.o` 引用 `foo`, `bar`；`lib1.a` 含 `foo.o`(定义 `foo`,引用 `baz`)；`lib2.a` 含 `bar.o`(定义 `bar`) 和 `baz.o`(定义 `baz`)。

**分析 1**：`gcc main.o lib1.a lib2.a`

| 步 | 文件 | U (未解析) | 动作 |
|:--:|------|-----------|------|
| 1 | main.o | {foo, bar} | |
| 2 | lib1.a | {foo,bar}→{bar,baz} | 拉 foo.o; 引入 baz |
| 3 | lib2.a | {bar,baz}→{} | 拉 bar.o; 拉 baz.o |

→ **成功**。

**分析 2**：`gcc main.o lib2.a lib1.a`

| 步 | 文件 | U | 动作 |
|:--:|------|----|------|
| 1 | main.o | {foo, bar} | |
| 2 | lib2.a | {foo,bar}→{foo} | 拉 bar.o; baz.o不拉(U中无baz) |
| 3 | lib1.a | {foo}→{baz} | 拉 foo.o; 引入 baz |

→ 扫描结束 U={baz}，**报错**（`baz.o` 在 lib2.a 中已被跳过，链接器不回头）。

#### ✏️ 真题训练

> **题3 (简答)** `main.o` 调用 `printf`(在 libc.a) 和 `sqrt`(在 libm.a)。以下哪些会报 `undefined reference to sqrt`？
> A. `ld main.o -lc -lm`  B. `ld main.o -lm -lc`  C. `ld -lc -lm main.o`

**答案**：仅 C。

**解析**：
- A：main.o → U={printf,sqrt}；-lc 拉 printf.o → U={sqrt}；-lm 拉 sqrt.o → 成功。
- B：main.o → U={printf,sqrt}；-lm 拉 sqrt.o → U={printf}；-lc 拉 printf.o → 成功。
- C：-lc 和 -lm 处理时 U={}，无拉入。main.o 后 U={printf,sqrt} 但再无文件 → 报错。

> **题4 (推导)** `main.o` 引用 `f`；`a.o` 定义 `f` 引用 `g`；`b.o` 定义 `g` 引用 `h`；`lib.a` 含 `x.o`(定义 `h`) 和 `y.o`(定义 `k`)。
> 命令 `ld main.o a.o lib.a b.o` 是否出错？

**答案**：出错，缺 `h`。扫描过程：main.o→U={f}；a.o→U={g}；lib.a→U 无 h，x.o,y.o 均不拉；b.o→U={h}→扫描结束无更多文件。**修复**：`ld main.o a.o b.o lib.a`（b.o 先于 lib.a 使 U 含 h）。

## 4.4 重定位

<a id="sec4-4-1"></a>
### 4.4.1 重定位信息  ★★★

#### 📌 考点概括
重定位条目记录"哪个位置的哪个引用需修正"，两种基本类型：PC 相对与绝对。

#### 📖 详细讲解

汇编器生成 `.o` 时不知外部符号最终地址，在引用位置生成重定位条目供链接器修正。

**重定位条目** (`Elf64_Rela`)：

```
┌────r_offset────┬──────r_info──────┬────r_addend────┐
│    8 bytes     │     8 bytes      │    8 bytes     │
├────────────────┼──────────────────┼────────────────┤
│ 需修正的位置偏移 │ 符号索引 + 类型   │   加数 A       │
└────────────────┴──────────────────┴────────────────┘
```

**两种常用重定位类型**（x86-64）：

| 类型 | 用途 | 典型场景 |
|------|------|---------|
| `R_X86_64_PC32` | PC 相对寻址 (32位) | `call foo`、`jmp` |
| `R_X86_64_32` | 绝对寻址 (32位) | `mov $array, %eax` |

`.rel.text` 存代码重定位条目，`.rel.data` 存数据重定位条目。

---

<a id="sec4-4-2"></a>
### 4.4.2 重定位过程  ★★★

#### 📌 考点概括
**PC 相对公式 `S + A − P`** 与 **绝对公式 `S + A`** ——本章最核心的计算题型。

#### 📖 详细讲解

链接器已知量：**S**=符号最终虚拟地址(链接器分配)，**A**=加数(`r_addend`)，**P**=被重定位处地址(`节基址+r_offset`)。

**核心公式**：

```
  PC相对: 修正值 = S + A − P  (若 A=−4 则目标 = S)
         执行时目标 = (P+4) + (S+A−P) = S + A + 4
  绝对:   修正值 = S + A
```
**记忆**："相对减 P，绝对不"。P = 节基址+r_offset（操作数存放地址），call 后下条指令 = P+4。

#### 🔍 举例推演：PC 相对重定位

> `swap.o` 的 `.text` 偏移 `0x0f` 处有 `call foo`（指令 `E8 00 00 00 00`）。
> 重定位条目：`r_offset=0x10, r_addend=−4, 类型=R_X86_64_PC32, 符号=foo`。
> 链接后：`.text` 基址 = `0x4004e0`，`foo` 地址 `S = 0x400510`。

```
已知: S=0x400510   A=−4   P=0x4004e0+0x10=0x4004f0

修正值 = S + A − P = 0x400510+(−4)−0x4004f0 = 0x40050C−0x4004f0 = 0x1C

验证: 执行后 PC=P+4=0x4004f4 → 目标=0x4004f4+0x1C=0x400510=S ✓
修正后指令: E8 1C 00 00 00 (小端)
```

#### 🔍 举例推演：绝对重定位

> `main.o` 的 `.data` 有 `int *p = &x;`（`x` 在其他模块）。
> 重定位条目：`r_offset=0, r_addend=0, 类型=R_X86_64_32, 符号=x`。
> 链接后：`.data` 基址 = `0x601020`，`x` 地址 `S = 0x601030`。

```
修正值 = S + A = 0x601030 → 写入 .data 偏移 0
加载后 *p = 0x601030，指向 x ✓
```

#### ✏️ 真题训练

> **题5 (计算)** 链接后 `foo.o` 的 `.text` 基址=`0x400500`。偏移 `0x14` 处有 `call bar`，重定位条目：`r_offset=0x15, r_addend=−4, 类型=R_X86_64_PC32`。`bar` 地址 `S=0x400560`。求修正后的操作数值（十六进制）。

```
已知: S=0x400560   A=−4   P=0x400500+0x15=0x400515
修正值 = 0x400560+(−4)−0x400515 = 0x40055C−0x400515 = 0x47
验证: 目标 = (0x400515+4)+0x47 = 0x400519+0x47 = 0x400560 ✓
```

**答案**：`0x47`

> **题6 (计算)** 链接后 `data.o` 的 `.rodata` 基址=`0x400620`，偏移 `0x08` 处有指针指向全局变量 `errmsg`。重定位：`r_offset=0x08, r_addend=0, 类型=R_X86_64_32`。`errmsg` 地址 `S=0x601040`。求写入该位置的 8 字节值。

修正值 = S + A = 0x601040 + 0 = 0x601040
写入值 = 0x0000000000601040 (小端: 40 10 60 00 00 00 00 00)

## 本章速查表

### ELF 各节速查

| 节名 | 存储内容 | 权限 | 占磁盘? |
|------|---------|------|--------|
| `.text` | 机器指令 | R+X | 是 |
| `.rodata` | 只读数据（字符串、跳转表） | R | 是 |
| `.data` | 已初始化全局/静态变量 | R+W | 是 |
| `.bss` | 未初始化全局/静态变量 | R+W | **否**（加载时清零） |
| `.symtab` | 符号表 | — | 是 |
| `.rel.text` | `.text` 重定位条目 | — | 是 |
| `.rel.data` | `.data` 重定位条目 | — | 是 |
| `.strtab` | 字符串表 | — | 是 |

### 符号规则速查

| 场景 | 结果 |
|------|------|
| 1 强 + 0 弱 | 选该强符号 |
| 1 强 + N 弱 | 选强符号，忽略弱符号 |
| ≥2 强 | **链接错误** (multiple definition) |
| 0 强 + N 弱 | 任选其一（通常选 size 最大者） |
| 0 强 + 0 弱 | **链接错误** (undefined reference) |

### 重定位公式速查

| 类型 | 公式 | 记忆 |
|------|------|------|
| `R_X86_64_PC32` | `修正值 = S + A − P` | **相对减 P** |
| `R_X86_64_32` | `修正值 = S + A` | **绝对不加 P** |

S = 符号地址，A = r_addend，P = 节基址 + r_offset

### 库顺序口诀

```
.o 在前 .a 在后，被依赖者放最后
单遍扫描不回头，顺序反了就报错
```
